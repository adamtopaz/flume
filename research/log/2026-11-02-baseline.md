## Plan

Measure flume v0 as merged (`15a7f62`) on the standard suite, so that every later
iteration has a committed reference measured with the merged harness.

## What was done

`python3 bench/harness/run.py --label baseline` on a clean checkout of `main`. `main`
and the candidate are the same commit, so the harness measured stock Lake and flume.

## Measurements

Standard suite (four 1,000-module corpora: three module-system shapes and one
ordinary-file corpus), CPUs 0-15, 32 GB, repetitions 3/10, 33 minutes:

```
speedup of candidate vs lake: cold=1.063x, noop=4.040x, leaf=1.298x, newfile=1.607x, hub-private=1.448x, hub-interface=1.052x, swarm=1.161x, clone=0.007x, agents-4=1.190x, workflow:single=1.569x, workflow:many=0.094x, workflow:cold=1.063x, overall=0.539x
correctness of candidate: identical artifacts to lake, all builds ok, break check ok
standard run: yes (suite standard)
```

Median wall-clock on `medium-layered`, Lake / flume: no-op 0.17 s / 0.04 s (most of
flume's 0.04 s is the harness's systemd scope), leaf 0.56 / 0.41, new file 0.25 / 0.18,
hub-private 0.36 / 0.25, hub-interface 41.5 / 39.2, swarm 2.17 / 1.88, cold 44.2 / 42.2,
agents-4 0.43 / 0.32, clone 0.27 / 43.1.

## Conclusion

- **Single checkout (1.57x):** flume's own overhead is already gone; what remains in leaf,
  new file, and hub-private is `lean` (start-up and import). P1 (a fork server) and P4
  (environment reuse) are the levers.
- **Many checkouts (0.09x):** entirely `clone`. Lake restores a fresh checkout from its
  artifact cache in ~0.3 s; flume rebuilds it in ~40 s. P2 (shared content-addressed
  cache) is the single most valuable next milestone for the overall number.
- **Cold (1.06x) and hub-interface (1.05x):** bound by `lean`'s CPU time on shared cores;
  P1, P4, and P5 (scheduling) target them.
